Ejercicio 5:

1.Solicitud: POST /api/usuarios
- Metodo HTTP: POST
- Endpoint recibido: /api/usuarios
- Servicio al que se dirige: Servicio de Usuarios.
- Justificacion: La ruta indica que va para usuarios y el metodo POST significa que se quiere
guardar o crear un usuario nuevo en la base de datos.

2.Solicitud: GET /api/productos
- Metodo HTTP: GET
- Endpoint recibido: /api/productos
- Servicio al que se dirige: Servicio de Productos
- Justificacion: La ruta apunta a productos y el metodo GET le avisa al sistema que el navegador 
solo quiere consultar o leer la lista de productos que ya existen.

3.Solicitud: POST /api/pedidos
- Metodo HTTP: POST
- Endpoint recibido: /api/pedidos
- Servicio al que se dirige: Servicio de pedidos.
- Justificacion: Va hacia la ruta de pedidos y usa POST porque la accion del usuario es registrar
una nueva orden de compra.

4.Solicitud: GET /api/usuarios
- Metodo HTTP: GET
- Endpoint recibido: /api/usuarios
- Servicio al que se dirige: Servicio de Usuarios.
- Justificacion: Aunque comparte la ruta usuarios con la primera solicitud, el metodo GET le indica
al backend que debe listar o leer los usuarios registrados en vex de crear uno nuevo.

5.Solicitud: POST /api/libros
- Metodo HTTP: POST
- Endpoint recibido: /api/libros
- Servicio al que se dirige: Servicio de Libros.
- Justificacion: Al recibir nuestro endpoint de libros con el metodo POST, el API Gateway identifica
que se quiere dar de alta un libro nuevo y deriva el JSON al backend de catalogo de libros.
